Agentic Adapter in Execution Time

MCP in the message path

How an IRIS interoperability production calls an MCP server while a message is in flight — which host does what, what crosses the production boundary, and where a language model does and does not sit.

The unit of work is a production. Five hosts, two of which carry adapters that reach outside. The example below enriches coded values in an HL7 message, but nothing in the shipped module knows what HL7 is — the same topology serves any message and any tool.

What actually happens to one message

Every hop below is a real production message, recorded in the Message Viewer with its own timing, its own body and its own retry behaviour. This is a trace taken from a running instance, not an illustration.

  1. HL7FileIn → EnrichCodesthe message arrives and is parsed
  2. EnrichCodes → SnomedMCPwhat tools does this server offer?
  3. SnomedMCP → EnrichCodesthe catalog, with input schemas
  4. EnrichCodes → ToolSelectorthe goal, the catalog, and the value in hand
  5. ToolSelector → EnrichCodesthe chosen tool, and why — usually from cache
  6. EnrichCodes → SnomedMCPcall that tool with these arguments
  7. SnomedMCP → EnrichCodesthe result
  8. EnrichCodes → HL7FileOutthe improved message, forwarded

Steps 2 to 5 disappear when the tool is known in advance. Configure a tool name, or map a field in the message to one, and a message costs a single call — no catalog fetch, no model, no cache. The model is an escape hatch for when the right tool genuinely cannot be known until the message arrives.

The model never touches the tool server

The two adapters have no connection to each other. Everything the model learns about the tool server arrives as text in a prompt, and everything it decides comes back as text. It holds no credentials for the server, has no network path to it, and cannot invoke anything.

The two methods are where the values live in my message and what to do with the answer. Everything else — the protocol, the catalog, tool selection, caching, error policy, the connections drawn above — is inherited. In the worked example that is 78 lines, and every line is about HL7.

If the shape does not fit

The base process assumes one common pattern: find several values, decide a tool for each, write the answers back. When your interface does something else — one call per message, routing on the answer, forwarding nothing — skip it. Any process, BPL or operation can send a tool request directly to the MCP item, and the adapter neither knows nor cares who called.
